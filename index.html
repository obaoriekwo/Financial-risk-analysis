Integration & automation

Feeding the executive dashboard pipeline

This engine is built to run headless and refresh Power BI on a schedule via Azure.
01 · EXPORT

Flat fact tables

Every run writes powerbi_risk_metrics.csv, powerbi_price_history.csv and powerbi_simulated_paths.csv — star-schema-ready tables for direct Power BI import or a Dataflow.

02 · SCHEDULE

Azure Function timer trigger

The risk_engine.py module runs inside an Azure Function on a daily timer, drops fresh CSVs into Blob Storage, and a Power BI Dataflow picks them up automatically.

03 · ALERT

Threshold-based reporting

A Logic App compares the new 95% VaR to the prior run; breaches beyond a configurable tolerance trigger an automated Power BI email report to risk officers.

Note

The attached dataset holds a single GS position, so this build demonstrates a single-asset portfolio. The engine itself is multi-asset — risk_engine.py takes a list of weighted holdings and derives a correlation matrix + Cholesky-factorized joint simulation automatically, so adding more tickers to the portfolio requires no structural changes.

Methodology

How the numbers are built

Simulation engine

Correlated Geometric Brownian Motion, drift & volatility estimated from daily log returns, joint draws via Cholesky decomposition of the covariance matrix — 20,000 paths per horizon.

VaR & CVaR

Monte Carlo VaR is the empirical loss quantile across simulated terminal P&L; CVaR (Expected Shortfall) averages losses beyond that quantile. A closed-form Gaussian estimate is shown alongside for comparison.

Supporting metrics

Sharpe & Sortino use a 4% annual risk-free rate; max drawdown is the worst peak-to-trough decline sampled across simulated paths, not just history.
